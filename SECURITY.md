# Security policy

## Supported version

Only the latest default-branch revision is supported. These portfolio demos are not production security controls, hosted services, authentication systems, compliance evidence, or safe destinations for sensitive data.

## Reporting

Do not publish exploit details, credentials, personal information,
employer/customer material, or production records. Use the repository's
**Security → Report a vulnerability** flow (GitHub private vulnerability
reporting). If that private flow is unavailable, withhold sensitive details
until it is restored.

Issues are disabled and pull requests are not reviewed. The checked-in bug
template is dormant scaffolding and does not create an active bug-intake or
response commitment.

## Scope

Reports may cover unsafe file handling, unintended network access, injection, path traversal, secret exposure, integrity-check bypass, or a documented boundary that the checked-in implementation violates. Design limitations already stated in project claim documents are not undisclosed vulnerabilities.
